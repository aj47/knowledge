# Vibe Coding Olympics — Format Notes

Source: Claude export conversation `Planning the first vibe coding olympics`
Date distilled: 2026-03-13

## Core concept
A live-streamed AI-assisted coding competition where builders use any AI tools to ship something useful fast.

## Decisions captured
- First event should be invite-only.
- Solo and team formats should be separate competitions.
- Winners should be chosen by audience vote.
- Building window should stay under 2 hours for stream energy.
- Best current format: **Mystery Box** challenge revealed live.

## Why Mystery Box works
- Prevents over-prep and template gaming.
- Creates a fairer live spectacle.
- Lets product thinking and execution show up under pressure.
- Makes the stream more watchable than generic hackathon coverage.

## Format draft
- Intro + rules: 5–10 min
- Challenge reveal: 5 min
- Build phase: ~90 min
- Demo phase: 15–20 min
- Audience voting + wrap-up: 10–15 min

## What makes vibe coding different
Traditional coding contests reward implementation depth and raw engineering speed.
Vibe coding competitions reward:
- product taste
- speed of iteration
- prompting/orchestration skill
- UX judgment
- ability to scope something shippable quickly

## Design constraints for good challenges
A challenge should:
- be understandable instantly
- be completable to a demoable state in 90 minutes
- allow visible variation in quality
- reward clarity and usefulness more than brute-force coding
- not require long setup or obscure domain knowledge

## Open questions to finalize later
- Should competitors share screens the whole time or only during demos?
- Is deployment required, or is local demo enough?
- Are there standard starter kits, or total freedom?
- Should judges exist in addition to audience voting?
- What anti-cheating rules matter for an invite-only pilot?

## Example challenge style
Good examples are prompts like:
- build a tool for a niche operator with a clear workflow
- build a tiny utility with a strong UX twist
- build around a surprising real-world constraint
